# 浏览器编年：代管陌生人的程序

> 你每天在自己的电脑上运行几十个陌生人写的程序，却从来没有点过一次「安装」。让这件事不出事的，是浏览器。
>
> 本文是浏览器三十余年的编年：一条暗线是**代管**——程序是别人的，机器是你的，中间站着浏览器；每扩大一层代管范围，就多一种出事方式，也多一条被迫写出的规矩。可与本库 [14](./14-internet-history-chronicle.md)（协议、入口与收束）、[10](./10-computing-cloud-chronicle.md)（计算如何池化）、[40](../40-paradigm/40-unix-agent-stateless-philosophy.md)（工具边界与沙盒）、[50](../50-strategy/50-ai-industry-disruption-strategy.md)（智能体入口尚未出现）对照：一篇写窗口如何卡位，本文写窗口内部如何替你挡。

先给一个直接答案：

> **浏览器真正的产品不是速度，是「你可以放心点开一个陌生链接」这件事。** 它替你去别人的服务器取回东西，在你的机器上把这些东西跑起来，同时尽量不让它们碰到不该碰的地方。三十多年里，代管的东西从文字扩到图片、脚本、视频、位置、摄像头，再到显卡；规矩从同源策略、弹窗拦截、多进程沙盒，到权限提示与默认 HTTPS。没有一条是先见之明——全都是先出事，再补。它并不是替你挑出了安全的网页；它是替你假设了每一个网页都不安全。

**10-chronicle 系列位置：** [10](./10-computing-cloud-chronicle.md)–[12](./12-artificial-intelligence-chronicle.md) 写计算、信息与智能；[13](./13-world-hegemony-transfer-chronicle.md) 写公共品与霸权；[14](./14-internet-history-chronicle.md) 写协议与入口。本文是**浏览器如何成为客户端上的代管人**：安全边界如何一层层赔出来。术语先看第 1.1 节。

## 摘要

浏览器把「从不认识的服务器取内容、在本机渲染乃至执行」做成日常，中间靠不断扩大的代管范围与被迫补上的规矩。1990–1993 年只代管显示（WorldWideWeb / Nexus、Mosaic）；1995 年 JavaScript 请进陌生程序，同源策略划下第一条数据边界；IE 与 ActiveX 把代管权做成生意并一度在沙盒上开洞；Mozilla 开源、Web 标准与 Firefox 把规矩移回公共文本并公开站在用户一侧；XMLHttpRequest 与 Ajax 让网页变成程序，Chrome 用多进程与低权限沙盒把「能做什么」关进进程；插件证明需求后被 HTML5 等能力内建再拆掉；权限模型开始代管「你本人」的能力；HTTPS 从可选变默认。今天 WebAssembly / WebGPU 把代管伸到硬件，Electron 一类壳把引擎嵌进桌面应用；消费级引擎收成 Blink / WebKit / Gecko 三套——开源不等于代管权不被事实集中书写。

**关键词：** 浏览器；代管；同源策略；沙盒；JavaScript；Web 标准；插件；权限；引擎集中；Chromium；Electron

## 1. 读法与术语

换个场合，每天运行几十个陌生人程序这件事相当荒唐——你不会随手双击邮件里的 `.exe`。网页却正是这么跑的，而且大多数时候没出事。程序是别人的，机器是你的，中间站着浏览器：这份差事，本文叫**代管**。下文按年代看代管范围如何扩大、规矩如何被迫补上；术语与边界先钉住。

### 1.1 术语对照

| 术语 | 一句话 |
| ---- | ------ |
| **代管** | 本文口径：浏览器替你取回并运行陌生人的内容，同时尽量限制它们碰到不该碰的地方。不是法律上的托管合同。 |
| **同源（same-origin）** | 协议、主机名、端口三者一致，才算同一来源。同源策略限制脚本读写跨源页面数据。 |
| **CORS** | 跨源资源共享：在同源策略之上，由服务器用响应头显式放行跨源读取。开发者撞见的「跨域」，多半先撞这条门禁。 |
| **沙盒（sandbox）** | 把渲染等进程关进低权限环境，即使页面被攻破，攻击者拿到的也是受限进程。 |
| **CSP** | 内容安全策略：用响应头限制页面能加载哪些脚本与资源，用来收窄 XSS 一类注入面。是同源之后的补丁层，不是取代同源。 |
| **渲染引擎** | 把 HTML / CSS / 脚本等变成屏幕上像素与可交互文档的核心组件。今日主流消费级市场主要由 Blink、WebKit、Gecko 三套覆盖。 |
| **Chromium** | Google 主导的开源浏览器项目；Chrome 基于它，Edge / Opera / Brave / Vivaldi / 三星浏览器等也多基于它或其分支 Blink。 |
| **插件（plugin）** | 浏览器外的运行时（如历史 Flash、Java applet），常自带另一套权限边界，难以被同一沙盒完整罩住。 |
| **权限模型** | 对摄像头、麦克风、位置等高风险能力默认拒绝，按来源授权、可撤回；技术规矩答不了「愿不愿意」，必须问你本人。 |
| **站点隔离（Site Isolation）** | 尽量把不同站点放进不同渲染进程，收窄跨站读内存、侧信道一类攻击面。 |
| **WebAssembly / WebGPU** | 让网页以接近原生的效率跑代码，并把 GPU 能力有条件地开给网页——代管范围伸到硬件。 |
| **Electron / CEF** | 用 Chromium（等）引擎把网页技术包成桌面应用。代管从「标签页」扩到「你以为的原生软件」。 |

### 1.2 边界

1. **本文写客户端代管，不写整部互联网史。** 协议、入口与注意力收束见 [14](./14-internet-history-chronicle.md)；浏览器在那条链上是「窗口」一层，本文把它剖开。  
2. **案例是论证口径，不是厂商判决。** 「Chrome 是不是新的 IE」只取可核对的同与不同：开源与标准参与是真的；引擎事实集中也是真的。  
3. **份额是页面浏览量统计的映射，不是安装量法庭。** 引擎占比由浏览器份额加总估算；iOS 强制 WebKit 会使「按品牌名加总」低估 WebKit、高估 Blink 的真实覆盖——正文标明口径。[^statcounter-engine]  
4. **隐私与广告政策会动。** 第三方 Cookie、Privacy Sandbox 等以厂商与监管当时公告为准；正文写的是「代管人身份冲突」结构，不冻结某一版产品路线图。  
5. **「倒挂」「守恒」是教学钩子。** 机器便宜、人变贵；麻烦换地方承担——可与工程常识对照，不替代一手文献。

## 2. 1990—1993：先只代管显示

### 2.1 1990 年 12 月：第一个浏览器也是编辑器

蒂姆·伯纳斯-李（Tim Berners-Lee）在 CERN 的一台 NeXT 工作站上写出了 WorldWideWeb，后来为避免和万维网本身混淆，改名 Nexus。它既能看网页，也能改网页。在最初的设想里，读和写本是同一件事——这个设想后来丢了很久，直到在线文档一类产品才算捡回来。[^cern-next]

<img src="https://commons.wikimedia.org/wiki/Special:FilePath/First_Web_Server.jpg" width="680" alt="CERN NeXT 工作站：第一台 WWW 服务器" />

**图 1｜CERN 的这台 NeXT 工作站既是伯纳斯-李写第一个浏览器的机器，也是万维网上的第一台服务器。** 机身上那张手写标签写着：这台机器是服务器，不要关机。图片：Coolcaesar，[CC BY-SA 3.0](https://commons.wikimedia.org/wiki/File:First_Web_Server.jpg) / Wikimedia Commons。
</div>

### 2.2 1993 年：让图文排在同一页

同期还有纯文字的 Lynx，以及 ViolaWWW、Cello 等图形浏览器。真正把网页变得「值得看」的是伊利诺伊大学 NCSA 的 Mosaic：它让图片和文字排在同一页上，不必点开另一个窗口。它不是第一个图形浏览器，但它是让普通人第一次觉得网页值得看的那一个。[^mosaic]

<div align="center">
<img src="https://commons.wikimedia.org/wiki/Special:FilePath/NCSA_Mosaic_Browser_Screenshot.png" width="680" alt="NCSA Mosaic 界面" />

**图 2｜NCSA Mosaic 的界面。** 图片和文字终于排在同一页上——这一步让普通人第一次觉得网页值得看。图片：Charles Severance，[CC BY-SA 4.0](https://commons.wikimedia.org/wiki/File:NCSA_Mosaic_Browser_Screenshot.png) / Wikimedia Commons。
</div>

### 2.3 这一代的边界

网页主要是一份死文件：一堆标记好的文字和图片。文件本身不能主动做什么，浏览器读完，自己决定怎么画。还没有脚本这个主动执行面，浏览器要防的东西也就少得多。

**所以 · 代管的边界挪到哪了：** 这一代只代管显示。内容是别人的，怎么呈现完全由浏览器说了算。下一条边界马上就要被推开：如果网页不只想被看见，还想做点什么呢？

## 3. 1995：请进第一个陌生程序

### 3.1 1994 年：网景

Mosaic 的主力开发者马克·安德森（Marc Andreessen）离开 NCSA，和吉姆·克拉克（Jim Clark）创办网景。Navigator 很快成了上网的默认方式。[14](./14-internet-history-chronicle.md) 把同一段写成入口卡位；本文只盯代管面如何被打开。

### 3.2 1995 年 5 月：十天做出来的第一个版本

网页需要一点点交互能力：一个注册表单，能不能在提交之前就检查邮箱有没有写错？布兰登·艾克（Brendan Eich）在 1995 年 5 月用大约十天，做出了第一个可用原型——是第一个可用版本，不是十天写完了一门完整的语言。它先叫 Mocha；随 Navigator 2 的测试版面向公众时叫 LiveScript；当年 12 月前后网景与 Sun 谈成合作，改名 JavaScript。改名是一次营销决定。这门语言和 Java 没有继承关系。[^js-hopl]

机器越来越便宜、人越来越贵——这里是极端一例：十天赶出来的东西，后来成了全世界唯一的通用客户端语言；三十年的代价，是所有人一起为当初那十天里的仓促决定打补丁。

### 3.3 第一道规矩：同源策略

网页从此能在你的机器上跑代码了。麻烦立刻跟着来。你同时开着网银和一个陌生论坛。论坛页面里的脚本，能不能读到网银页面里的内容？必须不能。

网景给出的答案就是**同源策略（Same-Origin Policy）**：一段脚本只能访问和它同源的页面数据；所谓同源，是协议、域名（主机名）、端口三样完全一致。这条规矩和 JavaScript 几乎同时出现在网景 Navigator 2 系列里，三十年后仍然是浏览器安全的地基。[^sop]

后来网页需要合法地跨源取数，才在同源之上长出 **CORS**（由服务器用响应头显式放行）。开发者天天撞见的「跨域」报错，源头仍是这条地基：默认不让过，例外必须被明文批准。

**所以 · 代管的边界挪到哪了：** 浏览器第一次代管执行——它开始在你的机器上运行陌生人的代码。同源策略确立了往后所有规矩的写法：先划一条线，规定陌生程序能看到什么。

## 4. 1995—2001：代管权成了生意

### 4.1 1995 年 8 月：IE 进场

微软把 Internet Explorer 随 Windows 95 的增值包发布，之后干脆装进系统。IE 随系统免费分发，而网景仍较依赖浏览器授权收入。[^ie-plus]

<div align="center">
<img src="https://commons.wikimedia.org/wiki/Special:FilePath/CHM_Artifacts_Boxed_Netscape_Navigator_(2273126105).jpg" width="560" alt="盒装 Netscape Navigator" />

**图 3｜盒装 Netscape Navigator。** 浏览器曾经是一件装在盒子里、摆在货架上卖的商品；IE 不要钱，改变的正是这件事。图片：计算机历史博物馆展品照片，[CC BY 2.0 系常见再授权口径](https://commons.wikimedia.org/wiki/File:CHM_Artifacts_Boxed_Netscape_Navigator_(2273126105).jpg) / Wikimedia Commons。
</div>

### 4.2 各写各的：「本站请用 IE 5 浏览」

两家用私有功能抢开发者。同一个效果，网景有一套写法，IE 有另一套；IE 还带来了 ActiveX，让网页可以调用 Windows 上的组件。于是网页开始在角落里挂出那行字：「本站建议使用 IE 5.0、1024×768 浏览」。代管权在谁手里，网页就得按谁的规矩写。

### 4.3 代价：把系统的钥匙递给网页

ActiveX 的问题不在技术名词，在边界：它让网页有机会碰到操作系统本身的能力。2000 年代前期那一整代浏览器劫持、莫名其妙的工具栏和满屏弹窗，很大一部分从这个口子进来。

1998 年美国司法部起诉微软捆绑，2001 年以和解收场。但市场早已定了：2002 到 2003 年前后，IE 各版本合计约占九成半（通行面板数字约 94%–95%）。[^ie-share]

**所以 · 代管的边界挪到哪了：** 这一代真正的教训不是「微软赢了」。**代管权一旦独家，规矩就由一家公司单方面写，而且可以写得对自己有利。** ActiveX 越过了上一节刚划下的那条线。它不是在沙盒里加功能，是在沙盒上开洞。

## 5. 1998—2008：把规矩收回公共手里

### 5.1 1998 年：把代码交出去

输掉市场的网景押了一注：开源。1998 年 1 月宣布，3 月放出代码，Mozilla 项目成立。团队随后做了一个更大的决定：推倒重写渲染引擎。新引擎叫 Gecko，代价是几年空窗期——重写期间拿不出像样的产品，IE 的份额正是在这段时间登顶。网景不只是被捆绑打败的，它也把自己的时间押了进去。[^mozilla-1998]

### 5.2 标准与一张公开的考卷

同一时期，W3C 推 CSS 与 DOM 标准，Web Standards Project 等运动游说厂商照标准做。后来的 Acid2、Acid3 把「合不合标准」变成一张任何人都能打开的测试页：画错了，一眼就看得出来。规矩第一次不再是某家公司的内部决定，而是公开文本，加一张公开考卷。[^acid]

<div align="center">
<img src="https://commons.wikimedia.org/wiki/Special:FilePath/Acid3_test_IE_vs_Firefox.jpg" width="680" alt="Acid3 测试对比" />

**图 4｜同一张 Acid3 测试页在两个浏览器里的结果示意。** 合不合标准不再靠各家自说自话，打开同一个网址就见分晓。此图为该测试的示例，非 2008 年当时的截图。图片：[Acid3 test IE vs Firefox](https://commons.wikimedia.org/wiki/File:Acid3_test_IE_vs_Firefox.jpg) / Wikimedia Commons（Acid 测试图通常视为公有领域）。
</div>

### 5.3 2004 年 11 月：弹窗拦截

Firefox 1.0 于 2004 年 11 月 9 日发布。它把已经出现的标签页和弹窗拦截进一步普及，并把「用户优先」做成醒目的产品立场。弹窗是网站想要的，不是你想要的。拦掉它，等于浏览器公开宣布：发生冲突的时候，我站在用户这边。[^firefox-10]

**所以 · 代管的边界挪到哪了：** 这一代没有扩大代管范围，而是换了立场：代管人第一次说明自己替谁工作。标准把规矩从公司手里移到公共文本，弹窗拦截把「用户优先」变成默认行为。这两件事是后面所有权限提示的前提——没有这一步，第 8 节那个「是否允许使用摄像头」的小窗口根本不会出现。

## 6. 1999—2008：网页开始像程序

### 6.1 1999 年：一个微软留下的零件

IE 5.0 里有一个叫 XMLHTTP 的组件，出自微软 Outlook Web Access 团队。它让脚本能在不刷新整页的情况下，再向服务器要一次数据。这件事值得写清楚：让网页变成应用的那个关键零件，出自浏览器大战里常被写成反面角色的那一方。其他浏览器后来把它实现为原生的 `XMLHttpRequest`。[^xmlhttp]

### 6.2 2004—2005 年：不用刷新的网页

Gmail 和 Google 地图用这个零件做出了新东西：拖动地图，内容自己补上，整页不动。2005 年，「Ajax」这个词把这套做法总结成一个名字。网页从「一份文件」变成「一个跑着的程序」，是在这几年完成的。随后 HTML5 与相关 API（画布、本地存储、音视频等）继续把「应用该有的零件」写进平台本身——下一节插件之死，正是这条线的收口。

### 6.3 2008 年 9 月：一个标签一个进程

Chrome（2008 年 9 月 2 日公开 Windows 测试版）带来两样东西。一是 V8，把 JavaScript 的执行速度提了上去，引擎从此进入军备竞赛。二是更要紧的那样：多进程把不同页面尽量隔离，并把渲染进程关进低权限沙盒。一个网页崩了，尽量不连累别的页面；一个网页被攻破了，攻击者拿到的是一个权限很低的进程。[^chrome-2008]

脚本能跑之后，另一类事故是**注入**：恶意脚本混进可信页面。业界后来用 **CSP（内容安全策略）** 等响应头，限制页面能加载哪些脚本与资源——这是同源之后的补丁层，用来收窄 XSS 一类口子，并不取代同源本身。[^csp]

2018 年起，Chrome 在桌面端默认启用站点隔离（Site Isolation）：尽量把不同站点放进不同渲染进程，进一步收窄跨站攻击与侧信道一类路径。[^site-isolation]

很多人抱怨 Chrome 吃内存。那正是价钱：内存换的是隔离。操作系统早就做过一遍进程隔离与权限削减；浏览器在自己肚子里又做了一遍——麻烦没有消失，只是换了地方由别人承担。

**所以 · 代管的边界挪到哪了：** 这一代代管的不再是文档，是程序。规矩也跟着升级：同源策略划的是「能看什么」，沙盒进程划的是「能做什么」。

## 7. 2007—2020：插件之死

### 7.1 插件曾经补齐了一切

浏览器做不到的事，长期由插件补上。Flash 负责视频、动画、小游戏和好看的字体，Java applet 负责复杂交互。2000 年代你在网上看到的大量视频，都是 Flash 放出来的。

### 7.2 2007—2010 年：一次拒绝

2007 年的 iPhone 不支持 Flash。2010 年 4 月，乔布斯发表《Thoughts on Flash》，列出耗电、不适配触屏、闭源等理由。争论很多，但有一条是结构性的，和好用不好用无关：插件维护着另一套运行时和权限边界，浏览器很难用同一套规则约束它，沙盒也很难完整罩住它。[^flash-jobs]

### 7.3 内建，然后拆掉

Web 平台把插件证明过有人要的能力，一项一项搬进浏览器自己：`<video>` / `<audio>`、画布、WebGL、本地存储、网页字体。YouTube 等大站转向 HTML5 播放，是需求已被内建接住的行业信号，不只是审美偏好。

Chrome 在 2015 年 9 月（Chrome 45）彻底移除了 NPAPI 插件接口；Flash 在 Chrome 里曾另走 PPAPI 等通道，直到 Adobe 于 2017 年宣布终止计划，Flash Player 于 **2020 年 12 月 31 日**正式停止支持。[^flash-eol] 不要把「拆掉 NPAPI」写成「当天全世界 Flash 一起死」——那是两段收口。

一个副作用：这也是很多老网页今天打不开的原因。它们没有坏，只是站在一扇已经被拆掉的门后面。

**所以 · 代管的边界挪到哪了：** 这一代把代管范围从「我能做的」扩到「你们想要的」，然后堵死了外挂通道。机制是固定的：插件先证明需求，浏览器再内建，接着拆掉插件。因为凡是自带另一套权限边界的东西，浏览器都没法替你担保。

## 8. 2010 年代：开始代管你自己

### 8.1 每一样都得先问

位置、摄像头、麦克风、通知、剪贴板、蓝牙。这些能力接进来的时候，前面几道规矩都不够用了。同源策略管的是数据边界，沙盒管的是进程权限，而摄像头是你本人的事——任何一条技术规矩都替你答不了「愿不愿意」。

于是有了那个所有人都眼熟的小窗口：「xxx 想使用你的摄像头」。这些高风险能力被放进一套默认拒绝、按来源授权、可以随时撤回的权限模型；站点还可用 Permissions-Policy（原 Feature-Policy）一类响应头，主动收窄自己页面能碰的能力。

### 8.2 加密从可选变成默认

早年只有付款页面才上 HTTPS，因为证书贵、配置麻烦。2015 年下半年 Let's Encrypt 开始免费发证并逐步被根信任，成本这道坎没了。2018 年 7 月，Chrome 68 把所有不加密的网站直接标成「不安全」。一条规矩要真正落地，往往得先让不守规矩变得难看。[^https-default]

### 8.3 挡住第三方

第三方 Cookie 让广告公司可以跨站跟着你走。Safari（智能防跟踪）、Firefox（增强跟踪保护）较早默认收紧；Chrome 因广告本身就是自家生意，第三方 Cookie 的淘汰时间表多次改写，并推出 Privacy Sandbox 一类替代方案——其后又宣布维持用户可选手动设置、不再单独弹窗推动全面淘汰。[^privacy-sandbox] 路线图会动；结构不变：代管人同时是你的代理人，和一家有自己生意的公司。

**所以 · 代管的边界挪到哪了：** 此前各节代管的多是别人的内容与程序；从这一节起，它开始代管你自己的感官与身份痕迹。规矩第一次必须问你本人：能力给不给，不再由浏览器一家静默决定。

## 9. 今天：长成操作系统的样子

### 9.1 能跑的东西越来越重

WebAssembly 让网页跑接近原生速度的代码；WebGPU（Chrome 自 113 起等逐步落地）把 GPU 能力有条件地开给网页。[^webgpu] Figma 在浏览器里做设计；VS Code 桌面版与许多「原生感」应用，内核是网页技术加 **Electron** / CEF 一类壳——你点的是安装包，跑的仍是浏览器引擎代管的那一套。今天打开一个网页，它可能正在调用你的显卡；打开一个桌面图标，它也可能是同一套代管换了外壳。

### 9.2 引擎三足与事实集中

约十余年前，主流引擎还更多；Opera 弃自研、微软 Edge 转向 Chromium（稳定版约 2020 年初）之后，消费级市场收成三套：**Blink**、**WebKit**、**Gecko**。按 StatCounter 2026 年 8 月全球页面浏览量粗加总：Blink 系（Chrome、Edge、Samsung Internet、Opera 等）约占 **78.7%**，WebKit（Safari）约 **15.8%**，Gecko（Firefox）约 **3.0%**。你看到的浏览器有一长串名字，底下的引擎只有三个，其中一个覆盖了近八成。[^statcounter-engine]

口径提醒：这是页面浏览量，不是安装量；且 iOS 上浏览器长期都必须用 WebKit，按「品牌名」把 Chrome for iOS 算进 Blink，会高估 Blink、低估 WebKit 的真实引擎覆盖。欧盟《数字市场法》等压力下，iOS 在特定区域开始允许替代引擎——规则在变，全球默认格局仍高度集中。[^dma-engine]

Mozilla 与 Open Web Advocacy 一类声音强调：引擎层若只剩大厂能养得起，Web 平台的议事日程就会更窄；Gecko 常被写成「仍跨平台、且不由操作系统巨头独养」的少数引擎之一。这是产业政治口径，正文只取「集中已发生、养引擎极贵」这一可观察事实。[^owa-engine]

### 9.3 Chrome 是新的 IE 吗

不同的地方是真的：Chromium 开源，标准和代码大多公开，外部贡献者也能参与，也可以拿走代码做自己的浏览器。这些当年 IE 都没有。

相同的地方也是真的：当一家公司的引擎事实上决定了一项新能力做不做、什么时候做，「标准」和「这家公司的实现」就很难分清。第 4 节那个教训——代管权一旦独家，规矩就由一家写——今天换了一种更体面的形式回来了。

**所以 · 代管的边界挪到哪了：** 代管范围已经扩到硬件与桌面壳：你的显卡、传感器、文件，以及大量「看起来不像浏览器」的软件。有资格划定这些边界的人，正在变少。

## 10. 尾声：你没点过的那次「安装」

回到开头。你今天打开了几十个网页，每一个都在你的机器上跑了陌生人写的代码，而你一次「安装」都没点过。这件事之所以不出事，不是因为网页温良，是因为浏览器在中间替你挡着。

而它手里那套规矩，是三十年一条一条赔出来的：

| 出事 / 压力 | 补上的规矩 |
| ----------- | ---------- |
| 脚本能跑了 | 同源策略（其后 CORS 管合法例外） |
| 弹窗泛滥了 | 默认拦截 |
| 网页变成程序了 | 多进程、低权限沙盒；CSP 收窄注入 |
| 插件带着另一套权限边界 | 能力被 HTML5 等逐项内建，插件被拆掉 |
| 浏览器开始碰你的摄像头和位置 | 每一次都要先问你 |
| 中间人可以偷看 | 加密从可选变成默认 |
| 引擎事实集中 | 开源可分叉，不等于议事日程不被一家牵引 |

没有一条是先见之明。全都是先出事，再补。

这也是为什么浏览器越做越大、越来越像一个操作系统：它要代管的东西越多，要替你守的门就越多。浏览器真正的产品不是速度，是「你可以放心点开一个陌生链接」这件事。它并不是替你挑出了安全的网页。它是替你假设了每一个网页都不安全。

下次网页弹出「是否允许使用你的位置」，那不是打扰。那是三十年里某一次出事之后，被写进来的一条规矩。

## 11. 本章要点

1. **代管：** 程序是别人的，机器是你的，中间站着浏览器；历史 = 扩大代管范围 + 被迫补规矩。  
2. **显示 → 执行：** Mosaic 只代管显示；JavaScript 代管执行；同源是地基，CORS 是显式例外。  
3. **独家风险：** ActiveX 在沙盒上开洞；代管权独家时，规矩可由一家写给自己。  
4. **公共规矩：** 开源、标准、Acid 考卷与弹窗拦截，把「替谁工作」说清楚。  
5. **文档 → 程序：** XHR / Ajax 之后是应用；Chrome 用进程隔离与站点隔离换内存；CSP 补注入口。  
6. **插件路径：** 证明需求 → HTML5 内建 → 拆掉外挂；凡自带另一套权限边界，浏览器难担保。  
7. **代管你自己：** 权限提示、默认 HTTPS、第三方跟踪限制——技术答不了愿不愿意；广告生意会拖慢收紧。  
8. **今天：** 代管伸到硬件与 Electron 壳；引擎三足而 Blink 事实集中——开源不等于权力不集中。

## 12. 参考文献

[^cern-next]: CERN / W3C 口述与展陈：伯纳斯-李在 NeXT 上开发 WorldWideWeb（后称 Nexus）；该机亦为早期 WWW 服务器。机身标签「This machine is a server. DO NOT POWER IT DOWN!」为通行展陈说明。

[^mosaic]: NCSA Mosaic（1993）：图文同页渲染推动大众采用。ViolaWWW、Cello 等图形浏览器更早或同期存在；「第一个图形浏览器」与「第一个让普通人觉得网页值得看的浏览器」不是同一句话。

[^js-hopl]: Allen Wirfs-Brock & Brendan Eich, *JavaScript: The First 20 Years*（HOPL IV / ACM）。1995 年 5 月约十天做出 Mocha 可行性原型；公开测试版以 LiveScript 出现于 Navigator 2.0 beta；同年 12 月前后更名为 JavaScript。十天不是「写完一门完整语言」。

[^sop]: Mozilla 归档文档 *JavaScript Security: Same Origin*：同源策略可追溯至 Netscape Navigator 2.0 系列；协议、主机、端口一致才同源。跨域报错是这条地基在工程上的日常显现。

[^ie-plus]: Internet Explorer 1.0 随 Windows 95 Plus! 于 1995 年 8 月发布；其后与 Windows 捆绑分发，改变浏览器作为独立商品的商业模式。

[^ie-share]: 通行面板与综述：IE 在 2002–2003 年前后合计份额约 94%–95%（如 OneStat 等当时公布的全球使用份额）；精确百分点随面板与方法而动，正文取「约九成半」方向。

[^mozilla-1998]: Netscape 1998 年开源 Navigator 代码，Mozilla 项目成立；随后以 Gecko 重写引擎，产品空窗与 IE 份额登顶重叠。因果是多线的，正文不写成单一「被捆绑打死」。

[^acid]: Web Standards Project 等推动的 Acid2 / Acid3：把标准符合度变成可公开打开的测试页。分数与截图随年代变化；图 4 为示意。

[^firefox-10]: Mozilla Foundation, Firefox 1.0 发布说明（2004-11-09）。标签页与弹窗拦截在更早版本与其他浏览器中已出现；1.0 的意义是普及与「用户优先」的产品立场。

[^xmlhttp]: Microsoft Exchange / Outlook Web Access 团队回顾：为 OWA 在 IE5 时代引入 XMLHTTP ActiveX，使脚本可异步向服务器取数；后标准化为 `XMLHttpRequest`。Ajax 命名（2005）是做法的总结，不是零件的发明日。

[^chrome-2008]: Google Chrome Windows 测试版公开于 2008-09-02；多进程架构与沙盒为产品设计核心卖点之一。V8 推动 JS 引擎性能竞赛。

[^site-isolation]: Chromium *Site Isolation*：桌面端自 Chrome 67（2018）起默认启用，尽量将不同站点放入不同渲染进程；用以缓解 Spectre 一类侧信道及跨站数据窃取路径。Android 策略更偏「登录站点隔离」，与桌面不全同。

[^flash-jobs]: Steve Jobs, *Thoughts on Flash*（2010-04）。结构性论点：插件另有运行时与权限边界，平台难以用同一套规则与沙盒约束。

[^flash-eol]: Chromium NPAPI 于 Chrome 45（2015-09）永久移除。Adobe Flash Player 正式停止支持日期为 2020-12-31；此前 Flash 在 Chrome 等产品中可走非 NPAPI 通道。老网页「打不开」常因外挂门被拆，不是文件本身必然损坏。

[^https-default]: Let's Encrypt：2015 年 9 月起发证并逐步获根信任交叉签名。Google Chrome 博客：Chrome 68（2018-07）起将 HTTP 页面标为 “Not secure”。

[^csp]: Content Security Policy（CSP）：以 HTTP 响应头限制页面可加载的脚本与资源，用于缓解 XSS 等注入。它是同源策略之上的纵深防御，不替代同源判定。

[^privacy-sandbox]: Google Privacy Sandbox 相关公告：第三方 Cookie 淘汰计划多次调整；约 2024–2025 年宣布维持 Chrome 既有「用户可在设置中选择」路径，不再单独弹窗推动全面淘汰。Safari ITP、Firefox ETP 为更早的默认收紧路径。正文取「代理人 vs 广告生意」结构，不冻结某一版 API 清单。

[^webgpu]: Chrome 开发者博客：WebGPU 随 Chrome 113 等版本面向稳定通道推进；其他引擎跟进节奏不同。正文用它说明代管已伸到 GPU，不是性能评测。

[^dma-engine]: 欧盟《数字市场法》（DMA）等监管压力下，Apple 在欧盟等区域调整 iOS 浏览器引擎限制（允许符合条件的替代引擎）。全球默认与区域例外并存；StatCounter 口径仍须单独阅读。

[^owa-engine]: Mozilla 政策博客与 Open Web Advocacy 等公开论述：主流引擎从更多套收束为 Blink / WebKit / Gecko；养引擎成本极高；Gecko 常被强调为仍跨平台的独立引擎之一。属产业与政策口径，非份额审计。

[^statcounter-engine]: StatCounter Global Stats 浏览器份额（如 2026-08：Chrome 69.39%、Safari 15.83%、Edge 5.36%、Firefox 2.98%、Samsung Internet 2.01%、Opera 1.94%）。引擎占比为按引擎归属加总的**页面浏览量**估算（Blink ≈ 78.7%，WebKit ≈ 15.8%，Gecko ≈ 3.0%）；非安装量审计。iOS 强制 WebKit（在未开放替代引擎的区域）会使「按浏览器品牌映射引擎」产生偏差。
